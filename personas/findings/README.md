# Findings

Retrospectives on the persona-based review methodology itself — how running Architect, Engineer,
and Challenger against real work actually went, not how it was supposed to go.

The three-role pattern in [../AGENTS.md](../AGENTS.md) is a claim about how to get better design
decisions. This folder is where that claim gets tested against outcomes. Each entry records one
real use: what the roles caught, what they missed, what the process cost, and what should change.

**Write one after any substantive multi-role review.** Be specific — the useful entry names the
finding, the cost, and the rule that should change. "It went well" teaches nothing.

Include what did *not* work. A folder of successes is a marketing page, and the process changes
worth making come almost entirely from the failures.

A finding is the *lesson*; the working material it came from lives in
[../artifacts/](../artifacts/). Keep them separate — retrospectives get read, draft piles get
skimmed, and merging them buries the former in the latter.
